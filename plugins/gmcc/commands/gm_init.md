# Initialize GM-CDE System

You are initializing the GM-CDE system at the user level.

**IMPORTANT**: This command creates the system-level `~/gmfs/` file
tree and builds/installs the three binaries — `gm_daemon` (the server that
owns the db), `gm_mcp` (the MCP pen), `gm_hook` (the shell-callable
client) — into `~/gmfs/bin/`. The daemon creates the `~/gmfs/` runtime dirs
and the SQLite db itself as it comes up. Per-project / per-instance /
per-session db rows are ensured lazily by
`scripts/gm_session_startup.sh` (`gm_hook context ensure`) on every
SessionStart.

---

## Pre-Flight Checks

1. `~/gmfs/` does NOT already exist (unless `--force` in `$ARGUMENTS`).

### If Already Initialized (Without --force)
Use AskUserQuestion:
```
GM-CDE system already initialized at ~/gmfs/

What would you like to do?
- Reinitialize (wipe ALL projects + kbites) - WARNING: This will delete ALL GMFS data
- Keep existing (exit without changes)
```

(Reinitializing never touches `~/gmfs/` — the db is managed separately, and
it is append-only history. Take a backup, `gm_hook call BACKUP --json '{}'`,
before any destructive db work.)

## Directory Structure Creation

Create the system-level structure:

```
~/gmfs/
├── README.md
├── _archive/cold_storage/               # universal archive bucket
└── projects/                            # artifact tree root (memory/*.md homes)
```

```bash
mkdir -p "$HOME/gmfs/projects" "$HOME/gmfs/_archive/cold_storage"
```

The `kbites/` subtree is created lazily by `/gm_crunch_open_maw` on first
kbite work. Per-project directories under `projects/{project_name}/` are
created lazily by `gm_session_startup.sh` on first SessionStart in a git repo.
There is no file registry — project/instance/session data lives in the
daemon db.

### README.md
```markdown
# GMCC GMFS (Context Knowledge File System) — v16

This directory contains GM-CDE file artifacts for all repositories.
Runtime DATA (projects/instances/sessions/prompts, file changes, artifact
pointers) lives in the daemon db at ~/gmfs/gm.db. Claude reads and writes
it through the MCP pen; shells and hooks use `gm_hook`.

## Structure

```
~/gmfs/
├── README.md                                  # This file
├── _archive/cold_storage/                     # archived material (structure-preserving)
├── projects/                                  # Artifact tree (auto-created per repo)
│   └── {project_name}/instances/{basename}_{hash4}/sessions/{sanitized_branch}/
│       └── prompts/{seq}_{name}/memory/       # usually empty (every report is a db row)
└── kbites/                                    # System-wide kbites (created on first kbite op)
    ├── {kbite_name}/KBITE_PURPOSE.md          # identity-level
    ├── digested/{kbite_name}/...              # persisted indexes
    └── open/{kbite_name}/...                  # in-progress maws
```

## Usage

1. Run `/gm_init` once to create this directory + build the binaries (already done)
2. Open Claude Code from any git repository — the SessionStart hook
   ensures the db rows + artifact dirs automatically
3. Run `/gm_bot` to start a workflow

## Environment Variables

The session env is emitted by `gm_hook context env` on SessionStart
(GM_BOOTED, GM_PLUGIN_ROOT, GM_FS_ROOT, PATH — plus GM_FS_ROOT when
sandboxed); all other paths come from `gm_hook paths --json`.

---
*Generated by GM-CDE v16*
```

## Install the binaries and bring the daemon up

```bash
bash "${CLAUDE_PLUGIN_ROOT}/scripts/install_gm.sh"
"$HOME/gmfs/bin/gm_hook" ping
"$HOME/gmfs/bin/gm_hook" status
```

`install_gm.sh` asks GitHub for the newest published `daemon-v*` release,
verifies its SHA-256 before unpacking, stages `gm_daemon`, `gm_mcp` and
`gm_hook` under `~/gmfs/bin/releases/downloads/<version>/`, and points
`~/gmfs/bin/` at them by symlink. It no-ops when that version is already
active, and refuses to replace a locally built `-BETA` without `--force`.

There is no source-build fallback — the plugin ships no Swift sources — so a
failure here is a network problem or an unpublished release, never a missing
Xcode. With a checkout of the repo, `bash gmk/scripts/rebuild_local.sh` builds
and activates without needing a release at all.

The first client call autostarts the daemon, which creates the `~/gmfs/`
runtime dirs, the log, and the db at the current schema. Surface the
`status` output so the user sees daemon pid + schema version. If the install
fails, warn and continue — the rest of init still completes; the SessionStart
staleness hook will keep reminding.

## Put `gm_hook` on the user's terminal PATH

No `~/.zshrc` env block — GMCC never writes shell profiles. Claude Code
sessions get `~/gmfs/bin` prepended to PATH automatically by
`gm_hook context env` at SessionStart, so nothing is needed for them.

For a plain terminal, PRINT the line and let the user add it themselves —
never edit their shell profile for them:

```
export PATH="${GM_FS_ROOT:-$HOME/gmfs}/bin:$PATH"
```

Writing it that way means one entry serves prod and every sandbox
generation, because the sandbox launchers set `GM_FS_ROOT`.

If a legacy `# >>> gmcc env >>>` block still exists in `~/.zshrc`, tell the
user to run `/gmcc_cleanup_system` — every variable in that block is
retired.

## Persist GMFS permission grant in ~/.claude/settings.json

Grants the plugin (and any subagent it spawns) unconstrained read/edit access to everything under `$GM_FS_ROOT`. `Read(path)` rules cover all file-reading tools (Read, Glob, Grep, …) and `Edit(path)` rules cover all file-editing tools (Edit, Write, NotebookEdit) — do NOT write separate `Write(...)` or `Glob(...)` rules; Claude Code ignores them and warns on startup. Without this grant the user is prompted for permission on every new file path the plugin touches outside the current project cwd — `~/gmfs/` is always outside cwd, so the prompts never end.

This is a one-time grant at **user scope** (`~/.claude/settings.json`). It applies to every repo on this machine and is inherited by subagents.

### Required keys

- `permissions.additionalDirectories` — must include `$GM_FS_ROOT` (Claude Code refuses file ops outside cwd without this, even with allow rules).
- `permissions.allow` — must include:
    - `Read($GM_FS_ROOT/**)` — covers all file-reading tools (Read, Glob, Grep, …)
    - `Edit($GM_FS_ROOT/**)` — covers all file-editing tools (Edit, Write, NotebookEdit)
    - `Bash(gm_hook *)` and `Bash(~/gmfs/bin/gm_hook *)` — hooks, ops and the raw passthrough run constantly (bare form resolves via the session PATH; absolute form covers bootstrap contexts)

`$GM_FS_ROOT` is expanded to its absolute value at write time — no `~` literal in the JSON.

### Idempotent merge

```bash
SETTINGS="$HOME/.claude/settings.json"
GMFS_ABS="${GM_FS_ROOT:-$HOME/gmfs}"

if ! command -v jq >/dev/null 2>&1; then
    echo "[GMB] WARNING: jq not found — skipping GMFS permission grant."
    echo "       Install jq (brew install jq) and re-run /gm_init to grant."
else
    mkdir -p "$(dirname "$SETTINGS")"
    [ -f "$SETTINGS" ] || echo '{}' > "$SETTINGS"

    TMP="$SETTINGS.gmcc.tmp.$$"
    jq \
      --arg dir "$GMFS_ABS" \
      --arg r "Read($GMFS_ABS/**)" \
      --arg e "Edit($GMFS_ABS/**)" \
      --arg w "Write($GMFS_ABS/**)" \
      --arg g "Glob($GMFS_ABS/**)" \
      --arg b "Bash($HOME/gmfs/bin/gm_hook *)" \
      --arg bb "Bash(gm_hook *)" \
      '
        .permissions //= {}
        | .permissions.additionalDirectories //= []
        | .permissions.allow //= []
        | .permissions.additionalDirectories =
            (.permissions.additionalDirectories + [$dir] | unique)
        | .permissions.allow =
            (.permissions.allow - [$w, $g] + [$r, $e, $b, $bb] | unique)
      ' "$SETTINGS" > "$TMP" && mv "$TMP" "$SETTINGS"

    echo "[GMB] GMFS permission grant present in ~/.claude/settings.json"
fi
```

Notes:
- `unique` makes the merge idempotent — re-running never duplicates entries.
- `- [$w, $g]` scrubs stale `Write(...)`/`Glob(...)` rules written by older /gm_init versions — Claude Code ignores those rule types for file permission checks and warns about them on startup.
- `//=` only initializes missing keys; existing `permissions.deny`, `permissions.ask`, and unrelated top-level keys (`env`, `enabledPlugins`, etc.) are untouched.
- Falls back to a warning (not a hard error) if `jq` is missing — the rest of `/gm_init` still completes.
- Takes effect on the **next** Claude Code restart. The current session has its permission set already loaded.
- `/gmcc_cleanup_system` detects drift on this grant (missing entries, moved `$GM_FS_ROOT`) and offers to repair using the same merge.

## Post-Initialization

1. **Verify Creation**:
   - Check that `~/gmfs/`, `~/gmfs/projects/`, `~/gmfs/_archive/cold_storage/`, and `~/gmfs/README.md` exist
   - Check that `~/gmfs/bin/gm_hook` exists and `gm_hook ping` succeeds (skip if the build was skipped — already warned)
   - Check that `~/.zshrc` does NOT contain a `# >>> gmcc env >>>` marker (if it does, point at `/gmcc_cleanup_system`)
   - Check that `~/.claude/settings.json` contains `Read($GM_FS_ROOT/**)` in `permissions.allow` and `$GM_FS_ROOT` in `permissions.additionalDirectories` (skip if jq was missing — already warned above)

2. **Report Success**:
```
[GMB] GM-CDE v16 system initialized!

Created:
- ~/gmfs/ (+ projects/, _archive/cold_storage/, README.md)
- ~/gmfs/bin/{gm_daemon, gm_mcp, gm_hook} + ~/gmfs/gm.db
- ~/.claude/settings.json: GMFS permission grant + gm_hook allowlist (bare + absolute form). Takes effect on next Claude Code restart; covers plugin subagents automatically.
- PATH line printed for plain terminals (sessions get it automatically)

Next steps:
1. Navigate to a git repository
2. Restart Claude Code — the SessionStart hook will ensure the db rows
   and artifact directories for that repo automatically
3. Run /gm_bot, /gm_bot_rpi, or /gm_bot_team to start a workflow
```
